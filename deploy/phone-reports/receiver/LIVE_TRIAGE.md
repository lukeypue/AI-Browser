# Live progress advisory triage

These source units extend the existing report backend with an event-driven advisory. They do not create a Codex review automation, execute app actions, patch code, or release software. Deployment is a separate explicit operation; no installer or running service is changed by adding these files.

`aibrowser-phone-live-triage.path` watches atomic writes in `/var/lib/aibrowser-phone-receiver/live` and invokes a single oneshot service. `live_triage.run_once` independently validates receipt hashes and strict phone progress, ignores stale/future documents and human-boundary snapshots, deduplicates canonical events by test ID, and groups matching typed failures. Three unique failures qualify. Missing control counters remain UNKNOWN; explicit zero and positive counts have separate groups.

A private SQLite store retains at most 4096 event hashes and 64 groups for 30 minutes. A process lock serializes all callers including model transport. Attempts are committed before transport and capped at six per rolling hour and 24 per rolling day; failures and crashes consume budget. One reservation per test/signature is retained across reopen. Results contain only the test ID, signature, repeat count, source, UTC timestamp, status, and validated advisory enums. A failed call persists MODEL_UNAVAILABLE without an error body. Freshness and signature validation remain the publisher's responsibility before private repository publication.

`triage_codex.CodexModel` validates its typed input again and sends only schema/source, allowlisted site/lesson/capability/page/diagnostic enums, safe control buckets, and repeat count. The model receives no URL, query, DOM, event text, receipt, device ID, or test ID. It returns exactly focus, next_check, confidence, and needs_human. Output is capped at 2048 bytes and independently enum-validated. Human-required output is advisory and never authorizes an action.

The supported installed CLI is `codex-cli 0.162.1`. The command starts `codex exec --ignore-user-config` (the ignore flag is exec-scoped), also uses `--ignore-rules --ephemeral --sandbox read-only --skip-git-repo-check --output-schema --output-last-message`, and reads the aggregate prompt from stdin. All tool-bearing supported features listed in `triage_codex.DISABLED` are disabled, including shell/unified exec, browser variants, computer use, apps/plugins/hooks, multi-agent, skills, dependencies, code mode and image tools. Web search is disabled, and host skill discovery is skipped. Each request uses a private temporary working directory with no repository. Subprocess environment is a fixed HOME/CODEX_HOME/PATH/LANG allowlist; stdout and stderr are discarded, and timeout is 120 seconds.

Normal root Codex sign-in is used internally by the CLI. This code never reads auth, configuration, keys, or cookies. The service runs as root to use that existing authorized sign-in; ProtectHome is read-only with only `/root/.codex` writable for the CLI's own auth refresh/runtime state. Root project and SSH directories are inaccessible, the filesystem is otherwise read-only, output is suppressed, and triage state is mode 0750 with the existing uploader group; the state database remains mode 0600 and typed latest output mode 0640. The model has tool features disabled and receives only the aggregate. Deployment must preserve these boundaries and must not copy root auth files or configure an API key.

To deploy later, install receiver.py, live_progress.py, live_triage.py, and triage_codex.py together in `/opt/aibrowser-phone-receiver`, create/verify the receiver live directory, install the two source units, and enable only the path after review. The existing single uploader must watch the triage state directory and publish validated fresh snapshots through its shared repository lock; do not add another repository writer. Unit installation, daemon reload, enabling paths, and uploader changes are not performed by this module work.

Verification uses fake subprocess transport for malformed input, strict args/schema, timeout, exit failure, oversized output and unknown output keys; receiver tests cover deduplication, human boundaries, TTL, state bounds, concurrency and attempt limits. A real authorized CLI request using the synthetic KSL/dismiss_dialog/DIALOG/NO_TARGET/ZERO/ZERO/repeat_count=3 aggregate succeeded and returned {"focus":"NO_SAFE_CONTROL","next_check":"CONTROL_DISCOVERY","confidence":"HIGH","needs_human":true}. This is synthetic adapter evidence, not consented phone evidence or an app fix.

The source trigger is prepared but must remain disabled until it is integrated with the identified existing review automation, or the maintainer explicitly replaces that arrangement. `upgrade-live.py` does not enable or start it. Do not create a duplicate review job.
