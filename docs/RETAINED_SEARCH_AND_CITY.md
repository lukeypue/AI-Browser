# Retained search recovery and aligned synthetic testing

The engine remembers failed procedures, proposes a distinct visible Submit-button procedure after a failed Enter, verifies changed results, and retains verified portable procedures. This is procedural learning; it does not train foundation-model weights or demonstrate real-site mastery.

## Evidence and reward

Typing a draft is not a submitted search. Search mastery requires changed result identities on a results page with the requested query applied. When a failed Enter already filled the draft, an exactly satisfied non-submit TYPE prerequisite can contribute to a program only if a required CLICK SUBMIT independently verified a mandatory ResultsChanged predicate. Unrelated navigation or permissive AnyOf predicates cannot supply that evidence. Omitted non-submit search TYPE expectations are normalized to the verifier's existing exact ValueIs default. The compiler receives an isolated composite proof copy, so the first successful repair is retained without changing the original ledger's actual causal-transition indices.

An unchanged refresh earns no new mastery. It is neutral only when exact committed URL query evidence agrees with the goal before and after; editable input is insufficient. Failed Enter and ignored Submit procedures survive memory reloads and remain held for the same relevant context.

SearchTransferEvaluationTest trains through actual engine execution with three changed control-ID sets and file-backed storage, reloads memory, and evaluates a new host/query/control-ID set without model calls. Its observed cold run used three actions and one failed Enter; retained execution used two actions, no failed Enter, and a compiled procedure. This is one held-out synthetic host, not a frozen evaluation of every real site. Evaluation runs can update their isolated outcome memory.
