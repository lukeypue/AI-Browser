# Verified procedural acquisition screen

This is an isolated pure-JVM experiment using the production BrainEngine, Planner parser, verifier, compiler and FileBrainStorage. It does not run a browser, Android or real websites. It does not modify running City/Android memory, contact a model automatically, publish reports, or install an app.

## Purpose and scope

The fixture has a visible inventory TAB prerequisite before search can commit. Whole-engine teacher-disabled baselines cannot solve it. A typed reference program establishes readiness. A separately authenticated teacher candidate is replayed unchanged; only the real engine can verify and compile it.

Eight held-out cases vary synthetic host, query, control IDs, ordering, region and tab tag within the same prerequisite transition structure. Call this semantic rebinding of one procedure, not broad structural transfer or marketplace mastery.

Learning-mode and FIND_LISTINGS arms report independently verified SEARCH outcomes. They do not establish full listing inspection.

## Repeatable commands

Use the existing pinned Gradle installation and a NEW empty experiment directory for each invocation:

- Scripted readiness: frontierScreen -PfrontierMode=scripted -PfrontierOutput=/path/to/new-output
- Capture an actual planner request: frontierScreen -PfrontierMode=capture -PfrontierOutput=/path/to/new-capture
- Replay an externally obtained candidate: frontierScreen -PfrontierMode=replay -PfrontierOutput=/path/to/new-run -PfrontierInput=/path/to/candidate-program.json
- Retain a previous experiment's failed-attempt memory during replay: append -PfrontierMemory=/path/to/prior-run/frozen
- Fresh-JVM evaluation: frontierScreen -PfrontierMode=evaluate -PfrontierOutput=/path/to/new-restart-check -PfrontierInput=/path/to/run/frozen

All are standalone core tasks. The Gradle JavaExec task starts a separate JVM. Compare procedure_hashes, frozen_memory_sha256 and the frozen files' before/after hashes; the mode label alone is insufficient restart evidence.

The replay label RECORDED_EXTERNAL_CANDIDATE does not authenticate a file. Establish source separately with the supported connection's request/response receipt and SHA-256 hashes. Do not edit a rejected model program into a passing program or attribute a scripted reference to a model. The fixture and captured request are synthetic only; the CLI does not grant permission to read phone or running-worker storage.

## Controls and credit

Every held-out row starts from its own durable fork of the frozen memory. Retained, cold and non-builtin-skill-removed arms use matching scenarios. Ablation preserves site bindings and failure evidence. Evaluation has no teacher client.

The oracle reads the renderer's committed query and prerequisite state independently of parsed semantic observations. No-op prerequisite, populated draft with non-working submission and human-only controls must earn no search/compiler credit. The draft negative deliberately uses a scripted stub to establish rejection readiness; it is not an external teacher call or a positive acquisition result.

Count new compiled procedures separately from curriculum completion and rehearsal. A passing experimental procedure is not automatically imported into Android or the existing City. Production integration requires a separate measured change and existing verification gates.

## Observed first external feedback experiment

On 2026-10-19 MDT, the first real structured Claude candidate reached the synthetic search oracle but included an ambiguous trailing WAIT. It earned zero compiled skills. Actual typed verifier feedback was sent through the protected Claude connection. Its revised response was replayed unchanged, retaining the prior failed-attempt memory (exact starting-memory hash matched).

That run acquired one compiled procedure. Teacher-disabled results: learning search 8/8 retained versus 0/8 cold and 0/8 skill ablation; ordinary search 8/8 versus 0/8 and 0/8. False verified claims were zero. A fresh JVM reloaded the persisted memory and repeated those results with identical procedure contracts, full frozen-memory hash and untouched original file bytes.

These are synthetic acquisition and retention results. They do not validate the physical phone, current real sites, automatic unattended teacher operation, or the unresolved Android process-death release blocker.

## Final source-chain and review verification

The stronger final run used an engine request captured from the clean preserved failure snapshot. The replay-time request matched those sent bytes exactly; full prompt, raw response, candidate program and starting-memory hashes were independently checked. The source-verified current-state encoding was included in the AI review after a proposal confused prior trial history with the current page. This is guided model-assisted acquisition, not autonomous capability discovery.

Request artifacts live in sibling exchanges/ directories, outside all BrainStorage roots. The report includes full safe compiled procedures and separates compiled_step_verified from compiled_procedure_verified. Whole-procedure verification derives from actual per-host skill success-stat increases; failed negatives are demoted. Typed aggregate fields fail closed. The human observation gate requires parsed human classification.

Final standalone core suite: 470 tests, zero failures/errors/skips, including eight new experiment regressions. The existing Android production sources and running workers are unchanged. Android app verification and the process-death investigation remain separate release gates.
