# Persistent server brain learning

The existing Practice City is a fresh-memory synthetic exam with scripted demonstrations. Keep it unchanged. Add a separate persistent, bounded server training loop using the real Kotlin engine/compiler/verifier, and the actually authorized server Codex CLI as a tools-disabled proposal transport. This is training infrastructure, not a duplicate review automation.

First capability: reusable search procedures across four synthetic marketplace profile styles corresponding to the current site group. Proposals are a strict typed search DSL with no selectors, URLs, personal text, commands or code. TYPE/SEARCH_BOX and CLICK/SUBMIT steps bind the synthetic task query locally. A proposal earns credit only after real engine execution and verified outcomes. Train on disjoint negative seeds/hosts, evaluate frozen candidate/current/cold memory on fixed held-out positive seeds/hosts with no teacher. Retain a candidate only for a strict success or action-efficiency gain with zero per-case regressions, zero unsafe actions and false mastery, plus demonstrated compiled reuse and memory-removal ablation. Equal/no-gain candidates do not count as upgrades.

Persist champion memory atomically with source/manifest/proposal/memory hashes and durable promotion history. Resume after restart, reject tampering, keep the previous champion until complete validation. A rejected or failed teacher cannot overwrite it. One controller lock; bounded reports and state. Cached JVM lab and four isolated synthetic Chromium workers keep each ordinary cycle fast; full checks precede installing lab updates. No actual-site accounts, phone data or APK publishing in this phase.

Server schedule: a continuous loop via systemd, one cycle per60seconds after prior completion. Four browser fixture workers use only intercepted synthetic pages. Model reservations before transport are limited to6/hour and24/day with at least15minutes between calls; failures consume budget. Quiet verified cycles keep evaluating champion without calling the model. Add new capabilities in follow-up iterations; search evidence does not establish four-site mastery.
