# 7.2.25 — distinguish challenge routes from ordinary hostnames

The frozen 432-case synthetic challenge exposed 18 blank-page cases incorrectly classified as CAPTCHA stops. A focused reproduction traced this to matching `/challenge` or `/checkpoint` across the URL scheme separator and an ordinary hostname beginning with that word. Remove the scheme separator before matching. Independent widget, phrase, explicit challenge-path and CAPTCHA-host markers remain protected; genuine human-only states are still redacted and never explored.

Regressions cover both hostname false positives, genuine protected routes, independent challenge signals, retained CAPTCHA-host handling, and bounded blank-page termination in both pagination modes. This is classification correctness, not recovery of an unavailable page or evidence of live-site mastery. The original exams, oracle, budgets, held-out fixtures and training isolation are unchanged. The separate challenge lab remains on its feature revision; this release does not deploy server code or import synthetic memory into Android.

Its failure signatures repeat earlier dialog/search/results observations and do not establish a source regression or the cause of those failures.
