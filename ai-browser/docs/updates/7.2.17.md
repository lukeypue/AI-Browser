# 7.2.17 — bounded teacher retries and honest loading evidence

The 7.2.16 phone test reached its full thirty-minute deadline with 132 attempts, 108 verified atomic actions and 75 procedure uses, but only one new lesson. Both KSL sources remained at 10/11 with Next page absent; Facebook remained at 6/11 with controls-free dialog observations. These counts do not establish the dialog's actual DOM or screen-off behavior.

Claude reviewed production source and recent updates; Gemini reviewed engine/curriculum/service excerpts. Unsupported pagination-deadlock, permanent paused-test wake-lock leak and release-version mismatch claims were corrected before implementation. The shipped scope is limited to reproduced engine faults:

- The first alternative teacher repair remains available after thirty seconds. Further unchanged failed states back off through 60, 120, 240 and at most 300 seconds. Relevant changed control shapes stay eligible immediately. The concrete failed-program hold and existing teacher on/off/budget settings remain. Saved failure counts no longer collapse to two on reload, so backoff survives restart.
- Non-numeric filter values require a full normalized label match. For example, Used does not verify against Unused, and Ford does not verify against Ford Mustang. Existing numeric display matching remains.
- Training a loading/pagination capability requires new result keys. Reaching the ordinary end of a list can still verify the navigation step, but does not create loading mastery or poison a valid procedure. A separate atomic step record handles saved programs replayed at the bottom without weakening causal evidence for mastery.

Regressions reproduced the original faults before their fixes. Independent code review caught an additional saved-program edge; its regression failed before correction. Existing valid end-of-list verification and positive pagination/replay tests remain in the core suite. Local compilation uses the official Kotlin 2.2.10 compiler and JUnit 4.13.2; CI runs the project's Gradle core/Android/browser checks and stable-signing release flow.

This update does not claim Facebook's controls-free dialog is fixed. Next page remains incomplete when the site only offers Load more. Previous saved lesson counts and user data are preserved; the stricter checks govern subsequent verification. It does not change the updater, signing identity, permissions, timed-test deadline, or login/CAPTCHA boundaries.

Install over the existing app, run a thirty-minute test, then save diagnostics. Compare new lessons, missing controls and teacher requests separately from repeated procedure uses.
