The two supplied diagnostics ending 1791681825/1791681830 are identical exports of a 7.2.13 test. Its deadline fired after 1,800,005 ms, so the timer ran thirty minutes. Useful actions stopped around minute four. The summary reports 168 attempts, zero verified actions/procedure uses and ten failed actions. ## Reproduced fixes
- Retain failed concrete procedure history and its six-hour hold. Allow one new AI repair proposal after the ordinary thirty-second retry, reserving the attempt before transport. Existing teacher budgets, master off switch, task limits and live verification still apply. This can increase AI usage when teacher help is enabled.
- Reload a settled non-dialog ERROR page through its known allowed search/start route once per probe, including when that URL is already open. Auth/challenge observations are handled first; busy pages and dialogs remain untouched. Recovery navigation earns no lesson credit.

Focused engine fixtures fail before the fixes and pass after them. Guards cover durable repair reservations, unchanged broken procedures, and human/busy/dialog boundaries. A fixture demonstrates a different teacher search procedure verifying while the original failed procedure remains held.

## Release and remaining limits
Version allocation remains owned by release automation; this patch does not change version numbers or signing configuration. A corrected signed APK retaining the existing version may require direct installation because the updater compares version codes.

These changes address reproduced recovery stalls. They do not prove live filter/dialog recognition is fixed or guarantee a new lesson on every retry. Further phone diagnostics are needed to measure actual learning after installation.
