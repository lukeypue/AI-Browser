# 7.2.18 — Check held prerequisites before starting lessons

The newest 7.2.17 phone run completed 30 minutes with 156 tasks, 119 verified actions, 19 failed actions and 86 verified procedure uses, but no new curriculum lessons. Facebook and OfferUp repeatedly ended tasks with recently failed approaches. KSL remained at honest 10/11 coverage with no observed Next page control.

A focused regression reproduced one new failed task despite persisted holds on the completed search prerequisite, its local repair, and teacher proposal route. The scheduler previously selected unfinished lessons from live targets without checking whether any procedure route was eligible.

Learning now checks the same concrete learned/builtin and local procedure keys used by execution before allocating a lesson. When all routes are held, it waits for the next normal site probe without incrementing the lesson ordinal or creating a failed task. An eligible fresh teacher repair, changed relevant controls, and different verified learned procedures remain available. Diagnostics report `procedure_cooldown` for the prevented attempt.

The source review included Claude, Gemini and an independent code reviewer. External suggestions were checked against source and the regression; unsupported claims about absent pagination and header closers were rejected. Copilot remained blocked by Microsoft sign-in. No live Facebook DOM or phone run of this new build was available during source review.

This release addresses task churn. It does not establish the cause of Facebook's controls-free dialogs or promise additional lessons on sites without the relevant controls. Pagination discovery and rehearsal remain follow-up review items.
